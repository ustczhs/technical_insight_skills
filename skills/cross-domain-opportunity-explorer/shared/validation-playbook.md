# 最小验证手册

先验证**最危险假设**，不先做完整软硬件。对照实验优先用**当前市售**替代物（≤12 个月可得），不用过时评测当基线。

| 最危险假设 | 首选低成本验证 | 关键观察 |
|------------|----------------|----------|
| 真实且高频的需求 | 深访、跟随观察、行为日记 | 具体事件、重复发生、现有绕路 |
| 用户愿意付费 | 价格访谈、预售页、定金、人工服务试点 | 真实承诺非口头「会买」 |
| AI 有独特价值 | 人工 Concierge、专家辅助、离线样本评测 | 明显优于规则/搜索/人工 |
| 硬件不可替代 | 手机/通用穿戴原型、模拟设备 | 实时、免手、传感器、物理介入 |
| 能持续使用 | 2–4 周试用、留存与停用访谈 | 频率、摩擦、充电佩戴、隐私 |
| **Itch 向：值得晒/展示** | 内容 mock、社群反应测试 | 是否真会发、互动与身份认同 |

睡眠、健康、康复等只能验证体验与行为支持；不能写成诊断或疗效。

涉及儿童、老人、位置、生物特征或音视频时，验证计划须写数据最小化、知情同意与退出机制。

## 与四杀伤的对应

| 四杀伤 | 验证重点 |
|--------|----------|
| 谁付钱 | 购买者与使用者分离访谈、预售/定金 |
| 为何付钱 | 相对替代的 A/B 价值锚 |
| 为何不是手机 | 对照实验：手机+配件 vs 专用形态 |
| 为何反复用 | 试用留存、吃灰场景访谈 |

## Handoff Route（不自动启动）

| 条件 | 建议路由 |
|------|----------|
| 证据/四杀伤/场景仍不足 | 本簇 **deep-dive** |
| 概念可作 Requirement Seed，值不值得做不明 | **`/requirements-review`** |
| 付钱逻辑已过，需竞品/技术/市场深证 | **`/hardware-insight`** |
| medical-boundary | 仅记录 + 人工合规；不进 shortlist |

写入 `HANDOFF_PACK.md` §8；用户显式决定后才可新开下游 skill。

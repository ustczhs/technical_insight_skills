# Hypothesis Grill（机会杀伤）

对 **candidate** 机会执行，默认由 Agent 写入卡片，**不**问用户。仅当「杀不死也活不透」时升级为 Decision Grill。

## 四杀伤假设（shortlist 硬门槛）

每项 candidate 必须可证伪地回答：

| # | 杀伤问 | 合格回答要点 | 常见死刑 |
|---|--------|--------------|----------|
| 1 | **谁付钱？** | 购买者≠使用者时分开；与 Cell 场景一致 | 「用户都会买」「年轻人」 |
| 2 | **为何付钱？** | 相对现状的具体损失或增益锚（时间/失败/安全/社交） | 「体验更好」「AI 很酷」 |
| 3 | **为何不是手机/通用穿戴？** | 约束透镜下的具体不可替代理由 | 「专用更专业」无场景 |
| 4 | **为何能反复用？** | 频率 × 摩擦；停用/吃灰风险 | 「每天都会用」无场景 |

## 扩展杀伤（写入卡片，不挡 shortlist）

| 问 | 用途 |
|----|------|
| 最危险假设是什么？ | 验证 brief 起点 |
| 现有替代方案为何不够？ | 证据段 |
| AI 的独特作用是什么？ | 非泛聊天 |
| 失效/误判后果？ | 风险段 |
| 吃灰/7 天停用场景？ | 留存杀伤 |

## 红队清单（形态）

对专用硬件/空间形态额外问：

- [ ] 手机 + 现有 App/配件是否 80% 解决？
- [ ] 通用运动相机/开放式耳机/手表是否已覆盖？
- [ ] 用户是否已有类似装备（沉没成本）？
- [ ] 充电/佩戴/配重/防水是否超过场景容忍度？
- [ ] 售后与丢失成本是否可接受？

## 输出位置

- 四杀伤 → `OPPORTUNITY_CARD` § 四杀伤
- 最大杀伤问题必须含场景摩擦，禁止单独「App 够吗」
- 扩展杀伤 → `OPPORTUNITY_CARD` § Hypothesis Grill 记录
- 否决理由 → `SPARK_BOARD` 晋升状态 = killed
- 升级问人 → 用 [grill-output.md](grill-output.md) 单题呈现

## 与 Spark 的关系

| 阶段 | 杀伤深度 |
|------|----------|
| Spark | 只写「最大杀伤问题」一列 |
| candidate | 完整四杀伤 + 扩展 |
| shortlist | 四杀伤齐 **且** ≥2 条时效内 fact/voice |

未写齐四杀伤 → 不得标 `shortlist`；可保留 `candidate` 或 `backlog`。

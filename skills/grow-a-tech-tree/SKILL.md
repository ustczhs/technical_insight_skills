# grow-a-tech-tree

通过 grill 交互，从目标产品/品类长出技术树：先叶清单（卡诺），再叶→枝→干→根。

**目的：** 结构化拆解技术组件，**识别关键技术以针对性投入**，从而提高产品竞争力。树不是完整 BOM/工程清单；节点取舍以「是否值得为竞争力而掌控或深投」为准。

本 skill 属于 Technical Planning Skill Package（包公约见仓库根 CONTEXT.md）。运行时产出仅写入 `trees/`。

术语权威：[CONTEXT.md](CONTEXT.md)。运行时速查与图例：[reference.md](reference.md)。层定义备忘：[refs/技术树四层.md](refs/技术树四层.md)。本地若有 `examples/` 可作对照（默认不入库）。冲突时以本 skill 的 `CONTEXT.md` 为准，并在会话中澄清。

## 硬规则

1. **一次只推进一个决策**，等待用户反馈后再继续。一次决策可以是「确认整份推荐清单」，但不要并行抛多个互不依赖的问题。
2. **每个决策必须带推荐答案**（候选节点、分层、停/再拆、依赖），用户只需同意/改写——禁止让用户对着空白枚举。
3. **推荐要高质量**：结合用户材料、本 skill `refs/`、本地可选 `examples/`、本会话已确认节点；需要时**尽量联网**核对最新公开技术信息。未确认的检索结果不得写入树。
4. **叶即竞争力特性**（客户价值）；**不要**在叶下再造「应用方案」伪叶。旧「××方案」视情况并入枝。
5. **多叶合并为一张 DAG**：节点按稳定身份去重（同名同层优先合并；有歧义先问）。
6. **未达共同理解前**，不要宣称树已完成；可按里程碑增量落盘中间态。
7. 能从仓库/上下文查到的事实自己查；**决策权在用户**。
8. **结构图必须遵守 reference 中的视觉约束**（叶三色、状态五色、单行分层、**曲线箭头连线**、标签格式）；落盘或用户改状态后，用 `scripts/sync_status_colors.py` 校正填充色。
9. **根/关键干聚焦竞争力杠杆**：只保留能抬高品类上限、差异化或能力天花板的关键技术。行业常规、标配工程做法（如通用 OTA、常规设备云管道、标准外设采购件且无延伸掌控必要等）**不要**写入根，也勿为凑完整架构强行占干/根席位；必要时在依赖补充中一笔带过即可。

## 会话流程

### 0. 启动

- 确认目标**产品或品类**名称；收集用户已有材料（文档、能力约束、本 skill `refs/`、本地可选 `examples/` 等）。
- 确定 slug（默认英文或拼音）与输出目录：消费方工作区 `trees/<slug>/`（与本地 `examples/` 区分）。
- 若目录已有 `tech-tree.md`，先读入并询问：继续生长 / 修订 / 新建。
- 结构图依赖：首次需要 drawio MCP 预览/导出前，运行  
  `bash <本包>/scripts/ensure-optional-deps.sh --only drawio`  
  （已配置则可跳过；写入 `~/.cursor/mcp.json` 后可能需重启 Cursor / 重载 MCP）。

### 1. 叶清单（卡诺）

- 推荐完整清单，按 **必备 / 期望 / 魅力** 分组；说明分类理由（可简短）。
- 用户确认或改写后，**立即**写入 `trees/<slug>/tech-tree.md` 首版（此时可无枝/干/根）。
- 请用户选出本会话要向下生长的 **一条或多条** 叶；未选中的只留在清单中。用户要求「完备/全覆盖」时，选定 = 清单全部。

### 2. 按叶向下生长

对每条选定叶，自上而下：

| 层 | 含义 | 判据要点 |
|----|------|----------|
| **叶** | 竞争力特性 | 客户价值属性；必备/期望/魅力；是入口也是顶层节点 |
| **枝** | 领域技术 | 领域内可复用模块；直接支撑叶；旧「应用方案」视情况并入 |
| **干** | 主干技术 | 可工程化集成的通用技术/平台/关键部件方案 |
| **根** | 根技术 | 决定范式与竞争力上限的底层能力/第一性单元；排除对产品提升有限的常规做法 |

每一步：

1. 给出**候选节点**（名称 + 所属层 + 支撑谁 + 简要理由）。
2. 给出 **停 / 再拆** 建议，依据 **掌控粒度**（本组织可掌握、外采或战略合作则为止）。
3. 对枝/干/根，从上下文**推断掌控状态**（必填其一）：**已实现 / 已实现可优化 / 规划中 / 外购合作 / 未实现**。叶不标掌控状态。「已实现可优化」= 已落地但仍有明确优化必要性。
4. 用户确认后更新 DAG，并按里程碑落盘。

全量生长时优先 **按层推进整张 DAG**（先全量枝→干→根），避免逐叶深挖导致重复与合并成本过高。

### 3. 里程碑落盘

在以下时机更新产物（同一套 DAG）：

- 叶清单确认后 → 首版 `tech-tree.md`
- 每完成一层（或一条叶拆到根）→ 更新 md + drawio
- 会话结束 / 定稿 → 总整理（补全依赖说明、图例、待决项）+ **导出 PNG 与 JPG**
- 每次写入/大改 drawio 后 → 跑状态色同步（见下）→ **再导出 PNG 与 JPG**（与 drawio 保持同内容预览）

产物路径：

- `trees/<slug>/tech-tree.md`
- `trees/<slug>/tech-tree.drawio`
- `trees/<slug>/tech-tree.png`（由 drawio 自动导出）
- `trees/<slug>/tech-tree.jpg`（与 png 同内容；可由 png 转出或 MCP/工具直接导出）
- 可选 `trees/<slug>/notes.md`（假设、待决、检索备忘）

### 4. 结构图（drawio）— 必须遵守

细节与色值见 [reference.md](reference.md)。摘要：

| 对象 | 约束 |
|------|------|
| 布局 | 产品在上；叶 → 枝 → 干 → 根向下；**每一类单行**；**四层色带同宽（取最长层）**；层内节点**分散居中**；图例/标题靠左紧凑；**色带加高、层间距充足、节点下移**；画布观感见 reference |
| 叶节点 | 仅名称，**不要**写「必备/期望/魅力」字样；用填充色区分三类 |
| 枝/干/根 | **两行标签**：第 1 行仅名称，第 2 行独占 `[状态：…]`（drawio XML 用 `&#10;` 换行，如 `名称&#10;[状态：已实现]`；勿与名称同一行）；**不要**在标签里写「叶/枝/干/根」 |
| 状态色 | 已实现=`#99FF99`；已实现可优化=`#E6FFCC`；规划中=橙；外购合作=紫；未实现=深红；枝/干/根**只按状态上色** |
| 字体 | 保证导出图可读：产品标题 ≥18（推荐 20）；色带层级标题 ≥16（推荐 17）；叶/技术节点 ≥13（推荐 15）；图例 ≥13（推荐 14）；勿用 10 作节点默认字号 |
| 图例 | 单行：`图例：` + 叶三色色块 + `标签颜色示意：` + 状态五色色块；左右色块**同间距**紧凑排列（勿把右侧状态色拉成大间距） |
| 连线 | **必须用曲线箭头**（见下）；禁止默认正交折线 |
| 工具 | 优先 drawio MCP（`user-drawio` / `drawio`）；缺则先跑包根 `scripts/ensure-optional-deps.sh --only drawio`。最终 XML 落盘 `tech-tree.drawio`；**完成后自动导出** `tech-tree.png` **与** `tech-tree.jpg`。无 MCP 时可用本 skill `scripts/gen_tech_tree_drawio.py` 生成 XML，再用桌面/CLI 导出预览 |

**连线（硬约束）：** 所有支撑边一律 **可见曲线箭头**，不得用 `orthogonalEdgeStyle` 直角折线。

- 方向：下层（支撑方）→ 上层（被支撑方）
- 默认 style：`endArrow=block;curved=1;edgeStyle=none;strokeColor=#666666`
- **必须带控制点**：仅设 `curved=1`、无 `points` 时 draw.io 仍画成直线。每条边的 `mxGeometry` 内至少要有一个非共线控制点，例如：

```xml
<mxGeometry relative="1" as="geometry">
  <Array as="points">
    <mxPoint x="…" y="…" />
  </Array>
</mxGeometry>
```

  控制点取源/宿锚点中点并做横向偏移（一对多时按扇出索引左右错开），使 Bezier 明显弯曲。
- 一对多 / 多对一：扇出不同 `exitX` / `entryX`，并与控制点错开配合
- 生成、编辑、从 MCP 回写后自检：边含 `curved=1`、**含** `as="points"`、**不含** `orthogonalEdgeStyle`；目视应为弧线而非直线

**手动改状态后的上色：** draw.io 不会自动变色。改完 `[状态：…]` 并保存后执行：

```bash
# 已 symlink 到 .cursor/skills/grow-a-tech-tree/ 时：
python3 .cursor/skills/grow-a-tech-tree/scripts/sync_status_colors.py trees/<slug>/tech-tree.drawio
# 或以本仓为工作区时：
python3 skills/grow-a-tech-tree/scripts/sync_status_colors.py trees/<slug>/tech-tree.drawio
```

脚本在本 skill 的 `scripts/` 下。Agent 在生成或修订结构图后也应运行，保证色与状态一致。

**字体（硬约束 + 观感推荐）：** 导出图须可读；优先用推荐字号，画布极紧时再退回下限。

| 对象 | fontSize 下限 | 观感推荐 |
|------|----------------|----------|
| 产品标题 | 18 | 20 |
| 色带层级标题（叶 · 竞争力特性 / 枝·干·根） | 16 | 17 |
| 叶节点、枝/干/根节点 | 13 | 15 |
| 图例 | 13 | 14 |

节点加字后若拥挤，同步加大节点宽高，避免裁切。水平方向：**四层色带同宽（按最长节点行）+ 层内分散居中**；图例与标题靠左；避免无意义超宽扁图。垂直方向：**加大层间距**使四层分隔清晰。节点很多时允许略放宽宽高比（详见 reference「画布观感」），**不要**为凑比例而压破单行或把字压到下限以下。

**自动导出 PNG + JPG（硬约束）：** 结构图落盘并完成状态色同步后，必须再导出预览图：

- 路径：`trees/<slug>/tech-tree.png` **与** `trees/<slug>/tech-tree.jpg`
- 优先用 user-drawio MCP：`load_diagram` → `export_diagram`（`format=png`）
- JPG：若 MCP 不直接支持 jpg，用 ImageMagick 等从 png 转出，例如 `convert tech-tree.png -quality 92 tech-tree.jpg`
- 时机：每次写入/大改 drawio 后；定稿时 png/jpg 须与最终 drawio 一致
- md 可链到 png/jpg，但 **不要** 用栅格图替代 drawio 作为可编辑源

### 5. 结束

- 复述：已覆盖叶、未拆叶、根落点、开放问题。
- 确认用户认可后，做最后一次总整理落盘，再跑一次状态色同步，并**导出最终 `tech-tree.png` 与 `tech-tree.jpg`**。

## 质量条

- 节点名具体、可被工程师识别（避免空泛「智能化」「平台能力」）；叶用客户可理解的价值表述。
- 层标签经得起 reference 中的边界测试；拿不准就提出推荐层并说明取舍。
- 根不无限下钻到纯学科/纯供应商内部（对照洗衣机例：停在仿真/算法/配方，而非工具厂商或控制论教材）。
- 根/关键干能回答「针对性投入它，产品竞争力会明显提升吗？」；答「只是行业标配/运维常规」则不应占根席。
- 推荐前后一致：后层必须能解释如何支撑已确认的上层。
- 结构图：叶三色、状态五色、单行、四层色带同宽且层内分散居中、层间距清晰、可见曲线（含控制点）、字体达推荐或至少下限、标签格式、色带标题不被遮挡、画布比例不过分扁长；且存在与 drawio 同步的 `tech-tree.png` 与 `tech-tree.jpg`。

## 不要做

- 不要在叶之下再造「应用方案 / ××方案」伪叶；应视情况并入枝。
- 不要在用户未确认时把联网结果写进正式树。
- 不要为每条叶复制整棵重复子树（应合并 DAG）。
- 不要一次抛出多个无关问题。
- 不要省略推荐答案。
- 不要在叶标签里写「必备/期望/魅力」，或在技术标签里写「叶/枝/干/根」。
- 不要给叶节点标掌控状态（状态仅枝/干/根；五态含「已实现可优化」）。
- 不要把 `[状态：…]` 与节点名称写在同一行；状态必须另起一行（drawio XML：`名称&#10;[状态：…]`）。
- 不要把「图例」二字单独悬在色块上方；图例须按 reference「图例布局」：`图例：`|叶三色|`标签颜色示意：`|状态五色（与叶色块同间距紧凑排列）。
- 不要把对竞争力提升有限的**常规做法**写入根（典型：通用 OTA、常规设备云/消息管道、无差异化的标准运维与采购黑盒）；亦不要为「架构完整」而堆砌此类干/根。
- 不要用正交折线（`orthogonalEdgeStyle`）作为连线；必须用带控制点的曲线箭头（`curved=1;edgeStyle=none;endArrow=block` + `points`）。
- 不要只写 `curved=1` 却省略控制点（视觉上仍是直线）。
- 不要在定稿或大改结构图后只留 drawio、忘记导出/刷新 `tech-tree.png` 与 `tech-tree.jpg`。
- 不要把节点/标题默认字号压到 10（导出预览会偏小难读）。
- 不要用省略号（`…`/`...`）截断叶/枝/干/根标签；完整表达技术条目，放不下则加高节点或改写表述。
- 不要各层色带各收各的宽，或把短层节点靠左挤成一坨；应**四层底框同宽（取最长层）+ 层内分散居中**；也不要为凑比例而无意义拉超宽空画布。
- 不要让四层色带贴得过紧；层间距应随字号/色带加高一并留足。
- 不要让状态文字与填充色不一致。

# grow-a-tech-tree

通过 grill 交互，从目标产品/品类长出一棵技术树：先用卡诺分析形成叶清单，再逐层落到枝、干、根。

本文件是本 skill 的领域术语权威。包公约见仓库根 [CONTEXT.md](../../CONTEXT.md)；选型术语（若查阅）见 [skills/soc-selection/CONTEXT.md](../soc-selection/CONTEXT.md)，与本 skill 无数据契约。

## Language

**叶**:
竞争力特性——对目标产品或品类做卡诺分析得到的客户价值属性，分为必备、期望、魅力三类。它是技术树的顶层节点，也是向下拆解的入口。一条叶下可挂多个枝。
_Avoid_: 应用方案层（勿在叶下再造「××方案」伪叶）, 功能点（未分类时）, 枝

**必备属性**:
顾客认为理所当然、缺失即不满的叶（竞争力特性）。

**期望属性**:
做得越好满意度越高、可线性比较的叶（竞争力特性）。

**魅力属性**:
超出预期、有则惊喜无则无妨的叶（竞争力特性）。

**叶清单**:
对目标产品或品类做卡诺分析后得到的必备/期望/魅力叶完整列表；是技术树生长的候选入口集。选定要生长的叶后写入 DAG 的叶层。
_Avoid_: 竞争力特性清单（旧称；现统一为叶清单）

**竞争力特性**:
叶的同义说法（客户价值属性）。文档与结构图中正式层名用「叶」。

**技术树**:
从选定叶向下生长的技术依赖结构，自上而下为叶、枝、干、根四层。一次会话先形成叶清单，再按选定的一条或多条叶分别向下生长；未选中的叶可只留在清单中。多条叶共用节点时合并为同一张可汇合结构（DAG），节点去重。

**枝**:
领域技术——特定领域内组件化、可复用的公共模块；直接挂在叶之下。若某能力已明显是跨产品复用的领域组件，直接标为枝（旧习惯里的「应用方案」视情况并入枝，不单独成层）。
_Avoid_: 叶, 干, 应用方案叶

**干**:
主干技术——可工程化复用、做产品时直接集成的通用技术、平台或关键部件方案。
_Avoid_: 根, 枝

**根**:
根技术——决定技术范式、核心特征和竞争力上限的底层能力或第一性单元（如材料配方、芯片、核心仿真与算法基座、基础工艺）。同一主题可与干成对出现（如干「IGBT模块」依赖根「IGBT」）。技术树用于结构化拆解并识别关键技术以针对性投入；对产品竞争力提升有限的行业常规做法不应作为根。
_Avoid_: 干, 通用 OTA / 常规设备云管道等标配工程（非竞争力杠杆）

**掌控粒度**:
拆解终止标准：落到本组织可投入掌握、外采或战略合作的能力单元即为止；再往下若已是供应商/学科通用能力且本组织无意掌控，则不再拆。每层由 Agent 建议「停 / 再拆」，由人拍板。

**掌控状态**:
枝/干/根节点的战略标注，取值仅限：已实现、已实现可优化、规划中、外购合作、未实现。叶是客户价值，不标掌控状态。「已实现可优化」表示已落地但仍有优化投入空间。交互中可从上下文推断；文档与结构图一致，结构图用固定状态色呈现。

**依赖**:
技术树节点间默认的支撑关系：下层支撑上层。不强制区分「因果」与「决定」；仅在会话中明确更强关系时，于文档补充说明，结构图可用不同线型可选标注。

**技术树文档**:
一次会话落盘的主产物：结构化 Markdown，包含叶清单，以及已选定叶向下生长出的叶/枝/干/根与依赖关系。按里程碑增量更新（清单确认后首版；每完成一条叶的一层或拆到根时更新；结束时总整理）。

**技术树结构图**:
与技术树文档配套的可视化产物，表达节点分层与依赖；默认格式为 drawio，需要时再导出 svg/png。与文档同步按里程碑增量更新。

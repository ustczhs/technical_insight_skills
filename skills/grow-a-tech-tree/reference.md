# grow-a-tech-tree — Reference

术语定义以 [CONTEXT.md](CONTEXT.md) 为准。本文件供运行时查阅：层边界例子、文档模板、色板与 drawio 约束、脚本。

## 层边界速查

| 易混 | 偏向 | 例子 |
|------|------|------|
| 叶 vs 枝 | 叶是客户价值；枝是实现它的可复用领域模块 | 「静音」=叶（期望）；「静音洗涤控制模块」=枝 |
| 伪叶（禁止） | 勿在叶下再写「××方案」当一层 | 「静音」叶直接 ← 枝，不要再插「静音洗涤方案」 |
| 枝 vs 干 | 枝偏领域模块；干偏可集成部件/平台 | 「高效逆变回路」vs「IGBT模块」 |
| 干 vs 根 | 干偏可集成部件/平台；根偏第一性基座 | 「IGBT模块」vs「IGBT」；「环路算法软件」vs「算法仿真」 |
| 关键根 vs 常规 | 根须能抬升竞争力上限；标配工程勿占根 | 「语音/情感算法基座」=根；「通用 OTA」≠根 |

## drawio 约定（硬约束）

### 布局

- 自上而下：产品标题 → 叶 → 枝 → 干 → 根。
- **每一类单行**排布。
- **四层色带同宽**：叶/枝/干/根背景底框宽度一致，取**节点行所需最长宽度**（通常为节点最多的一层），短层不单独收窄。
- **层内分散居中**：在统一色带宽度内，该层节点水平**均匀分散**并整体居中（等间距铺开）；不要靠左挤成一坨，也不要为「拉满超宽 page」而把色带无意义加宽。
- **层间距**：色带之间留出清晰空隙（可略大于色带内边距），避免四层贴太紧；加字号后同步加高色带与层间距。
- 图例与产品标题仍靠左紧凑排列；色带与节点行相对画布亦可整体略偏左，但以内容定宽，避免细长空画布。
- 每层左侧（色带顶部）标注层级名称（「叶 · 竞争力特性」「枝 · 领域技术」等）；节点内不再重复「叶/枝/干/根」字样。
- **层底框必须加高**：色带高度需明显高于节点高度，并在色带顶部为层级标题预留独立空白（节点整体下移），避免最左侧节点压住层级标题文字。参考：色带高度约 140–160、标题区约 30–40、节点置于色带下半区。
- 图例放在标题旁或标题下一行靠左，说明叶三色与状态五色；**布局硬约束**见下「图例布局」。

### 画布观感（软约束，勿勉强）

导出 PNG/JPG 应易读、比例协调；以下为优先目标，**节点过多时允许放宽，不要为凑比例而过度压窄节点或改破「单行」硬约束**。

| 目标 | 建议 | 说明 |
|------|------|------|
| 画布宽高比 | 约 **1.5–2.2 : 1** | 避免无必要的超宽扁图（如 &gt;3:1）；节点很多时可略超 2.2 |
| 水平策略 | 四层色带同宽（按最长层）+ 层内分散居中 | 禁止「各层各收窄」或「整页无意义超宽」作为默认 |
| 垂直策略 | 色带加高、**层间距充足** | 字号加大后同步加高节点、色带与层间空隙 |
| 节点尺寸 | 叶约 ≥170×56；枝/干/根约 ≥170×70 | 两行状态标签不裁切；根层节点特多时可略减宽，优先保字号 |

自检：打开导出图，四层底框是否齐宽？短层节点是否在底框内均匀居中而非挤向一侧？层与层是否留白清晰？文字是否一眼可读？

### 叶：配色与标签

节点**只写叶名称**，禁止在标签中写「必备 / 期望 / 魅力」。类别仅用填充色表达：

| 类别 | fillColor | strokeColor |
|------|-----------|-------------|
| 必备 | `#F8CECC` | `#B85450` |
| 期望 | `#F4B183` | `#C65911` |
| 魅力 | `#DAE8FC` | `#6C8EBF` |

### 枝 / 干 / 根：标签与状态色

标签格式（**硬约束：状态独占第二行**）：

```text
节点名称
[状态：已实现]
```

drawio 落盘时：节点须 `html=1`，value 使用 `名称&#10;[状态：…]`（`&#10;` 为换行）。**禁止**写成 `名称 [状态：…]` 单行——导出预览中状态必须另起一行可见。勿依赖裸 `\n`（写入 XML 属性易被压成空格）或不可靠的 `<br>`。

禁止在标签中写入「叶」「枝」「干」「根」。叶节点不要写 `[状态：…]`。

枝/干/根**只按掌控状态上色**（状态色覆盖层默认色）：

| 状态 | fillColor | strokeColor | fontColor |
|------|-----------|-------------|-----------|
| 已实现 | `#99FF99` | `#33AA33` | `#000000` |
| 已实现可优化 | `#E6FFCC` | `#99CC66` | `#000000` |
| 规划中 | `#FFE6CC` | `#D79B00` | `#000000` |
| 外购合作 | `#E1D5E7` | `#9673A6` | `#000000` |
| 未实现 | `#A61C00` | `#660000` | `#FFFFFF` |

层色带仅作分区背景（半透明），不决定节点填充色。

### 图例布局（硬约束）

图例须为**单行横向**，自左向右：

1. 文案 **`图例：`**（紧贴其右为叶类别色块，勿单独悬在色块上方）
2. 叶三色色块依次：**必备 → 期望 → 魅力**
3. 文案 **`标签颜色示意：`**（位于「魅力」右侧、「已实现」左侧）
4. 状态五色色块：**已实现 → 已实现可优化 → 规划中 → 外购合作 → 未实现**，紧接「标签颜色示意：」之后横向排列；**色块间距与左侧叶三色色块间距一致**（固定小间距，如 8px），**不要**为填满画布而把状态色块拉成大间距均布。

禁止：把「图例」二字单独放在色块上方；禁止状态色块挤成一坨或与叶色块混排无分隔文案。

### 字体（可读性硬约束 + 观感推荐）

导出 PNG/JPG 后文字须清晰可读。

| 对象 | 下限（硬） | 观感推荐（软） |
|------|------------|----------------|
| 产品标题 | ≥ 18 | **20** |
| 色带层级标题 | ≥ 16 | **17** |
| 叶 / 枝 / 干 / 根节点 | ≥ 13 | **15** |
| 图例 | ≥ 13 | **14** |

- 节点标签须写**完整技术条目**，禁止用 `…`/`...` 截断；放不下时优先**加高节点**（`whiteSpace=wrap` 自动换行），其次才考虑在 md 中改写更短但仍完整的表述。
- 节点加字后若拥挤，同步加大节点宽高，避免文字裁切或压住色带标题。优先用观感推荐字号；画布极紧时再退回下限，仍须同步增加节点宽高，避免文字裁切或压住色带标题。

### 边（连线）— 曲线箭头硬约束

- 方向：下层（支撑方）→ 上层（被支撑方）。
- **一律可见曲线箭头**，禁止直角正交折线，也禁止「标了 curved 却仍是直线」。
- 默认 style（必填字段）：

```text
endArrow=block;curved=1;edgeStyle=none;strokeColor=#666666
```

- `curved=1` + `edgeStyle=none`：按控制点画 Bezier；`endArrow=block`：实心箭头指向被支撑方。
- **控制点必填**：两点连线即使 `curved=1` 也是直线。每条边必须在 geometry 中提供至少一个**不与源宿共线**的控制点：

```xml
<mxGeometry relative="1" as="geometry">
  <Array as="points">
    <mxPoint x="中点X+横向偏移" y="中点Y" />
  </Array>
</mxGeometry>
```

  推荐：控制点 = 出边锚点与入边锚点的中点 + 横向 bulge（同层一对多时按扇出索引正负错开，近垂直边至少偏移约 28px）。
- 一对多 / 多对一时：为各边分配不同的 `exitX` / `entryX`（扇出/扇入），并与控制点配合避免重叠。
- **禁止** `orthogonalEdgeStyle`、`elbowEdgeStyle` 等折线路由作为默认（含 MCP 编辑回写后）。
- 验收：打开 drawio，连线应为**平滑弧线**；XML 中每条支撑边含 `curved=1`、含 `as="points"`、不含 `orthogonalEdgeStyle`。
- 「决定上限」等强关系：在上述曲线 style 上加 `dashed=1;strokeColor=#B85450`，并在 md「依赖补充」写明。

### 状态色同步脚本

路径（随本 skill）：`scripts/sync_status_colors.py`（symlink 后为 `.cursor/skills/grow-a-tech-tree/scripts/…`）。

draw.io 不会根据文字自动改色。生成图、或用户手动改了 `[状态：…]` 之后，运行：

```bash
python3 .cursor/skills/grow-a-tech-tree/scripts/sync_status_colors.py $PROJECTS_ROOT/<project_slug>/trees/tech-tree.drawio
# 或以本仓为工作区：
python3 skills/grow-a-tech-tree/scripts/sync_status_colors.py $PROJECTS_ROOT/<project_slug>/trees/tech-tree.drawio
```

脚本读取带 `[状态：…]` 的枝/干/根节点，按上表重写 fill/stroke/fontColor。状态文案必须是五态之一，否则脚本告警跳过。叶节点无状态行，脚本应跳过它们。

### MCP

若存在 drawio MCP（`user-drawio` / `drawio`）：用其创建/编辑/预览，并保证仓库内 `$PROJECTS_ROOT/<project_slug>/trees/tech-tree.drawio` 与会话一致。若未配置，先跑包根 `scripts/ensure-optional-deps.sh --only drawio`。无 MCP 时仍可用本 skill 脚本生成 XML：

也可从 `tech-tree.md` 按本文件布局约定生成结构图：

```bash
python3 .cursor/skills/grow-a-tech-tree/scripts/gen_tech_tree_drawio.py $PROJECTS_ROOT/<project_slug>/trees/tech-tree.md
python3 .cursor/skills/grow-a-tech-tree/scripts/sync_status_colors.py $PROJECTS_ROOT/<project_slug>/trees/tech-tree.drawio
```
**自动导出 PNG + JPG（完成后必做）：**

1. 状态色同步完成后，`load_diagram` 加载 `$PROJECTS_ROOT/<project_slug>/trees/tech-tree.drawio`
2. `export_diagram` 导出到 `$PROJECTS_ROOT/<project_slug>/trees/tech-tree.png`（`format=png`）
3. 再得到 `$PROJECTS_ROOT/<project_slug>/trees/tech-tree.jpg`（MCP 若无 jpg：`convert $PROJECTS_ROOT/<project_slug>/trees/tech-tree.png -background white -flatten -quality 92 $PROJECTS_ROOT/<project_slug>/trees/tech-tree.jpg`）
4. 定稿与每次大改结构图后都要刷新 png/jpg，使其与 drawio 一致

无 MCP 时：可用 draw.io 桌面/CLI 等价导出，但仍须落盘同名 `tech-tree.png` 与 `tech-tree.jpg`。svg 可选，png+jpg 为默认必出物。

## 推荐质量提示

- 先对齐品类边界与用户约束（成本、供应链、自研红线），再出节点。
- 联网时优先查：主流技术路线、关键器件/工艺、近年代际变化；注明来源日期，写入树前二次确认。
- 同一会话内复用已确认措辞，避免同义重复节点。
- 推荐枝时：若自然想写「××方案」伪叶，改为直接写可复用模块作枝，支撑对应叶。

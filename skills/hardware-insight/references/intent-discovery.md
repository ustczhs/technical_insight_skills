# 意图发现与问询（Step 0–2）

内嵌 brainstorming（语境扫描、一次一题、分段确认）与 grilling（决策树压测、事实自查、共识前不执行）思想。**不 invoke** 外部 skill。

**读取边界**

- Step 1–8 **只读** `调研基调.md`
- `调研意图.md` 供人回顾与 Step 0 续跑；后续步骤**不得依赖**

---

## A. 交互纪律

1. **一次一题**：等用户答完再继续；同一轮开放题不得连发多条。
2. **消息分离**：开放题与 `AskQuestion` **不得**出现在同一条消息。
3. **事实 vs 决策**
   - **事实**（产品是否存在、已有 `$PROJECTS_ROOT/*/research/`、公开规格、在售状态）：agent 自行 WebSearch / 读仓库，**不问用户**。
   - **决策**（T0 边界、深度、必证项、**分析师立场**、我方主体、明确不做、成功标准）：**必须问用户**并等待。
4. **推荐答案**
   - **结构化选择题**（深度、范围、读者、扩展包等）：给出推荐 + 理由，用户确认或修正。
   - **开放决策题**（决策赌注、失败是否算成功等）：**只问不推荐**，避免先入为主。
5. **共识闸门**：`调研基调.md` 中 `Step 0 状态` 为 **已确认** 前，**不得进入 Step 1**。
6. **交错写入**：问询过程中随时更新两文件草稿；不必等全部问完再落盘。
7. **题量上限**
   - Step 0 full grill：**最多 8 轮**开放题
   - Step 0 简流程：**1–3 轮**开放题
   - Step 1 / Step 2 轻量 grill：各 **最多 3 轮**

---

## B. 清晰度分流（agent 启发式）

无硬 checklist；agent 综合判断后选择 **full grill** 或 **简流程**。

### 模糊信号（倾向 full grill，≤8 轮）

- 缺**决策赌注**：说不清调研结束后要做什么决定
- **调研议题**一句说不清，或同时含多个未拆解子课题
- **范围过大**（如「全球所有 XX 硬件」）且未说明裁剪方式
- **我方主体**不明或未确认（第一方模式下）
- **分析师立场**未确认（无默认；须用户自填或选中立）
- 仅有品类/赛道，无具体对标或决策命题
- 用户输入与已有 `$PROJECTS_ROOT/<project_slug>/research/` 产出明显冲突且未澄清

### 清晰信号（倾向简流程，1–3 轮）

- 有明确**决策命题**（如「X 能否用于 Y」「是否立项 Z」）
- 产品/品类/对标可识别
- 读者或调研目的已隐含或可快速确认
- 可参考已确认项目的 `调研基调.md` 结构（议题 + 核心决策问题 + 分层）

### 模糊输入专用：调研策略对比（一次）

在 full grill 中段，当议题初步成形时，给出 **2–3 种调研策略**（带推荐）：

| 策略 | 适用 | 代价 |
|------|------|------|
| **广度优先** | 品类扫描、机会探索 | T0 较浅，T2 较多 |
| **T0 深拆** | 已有明确对标，需硬证据 | 耗时，范围宜收窄 |
| **假设驱动** | 已有 3–5 条核心决策问题 | 模板与竞品列表强裁剪 |

---

## C. 问题库

### C.1 开放决策题（无推荐答案）

按需选用，一次一题：

1. **决策赌注**：这份调研结束后，你要做哪一个具体决策？（立项/砍项/选路线/融资叙事/其他）
2. **成功标准**：什么结论出现，你会说「调研成功了」？
3. **失败标准**：若结论是「不建议做/不结合」，报告算成功还是失败？
4. **时间敏感**：是否有硬 deadline（展会、董事会、竞品发布）？
5. **证据底线**：哪些结论必须 A 级证据？哪些可接受学术基线？
6. **明确不做**：本次调研**不回答**什么？（BOM 深度、法务、供应链询价等）

### C.2 假设压测（grill）

在 agent 形成初步假设后，用「假设 → 若错误则代价 → 请确认/修正」格式挑战：

- T0 名单是否选对？是否有更强对标被遗漏或误标 T2？
- **深度 × 范围 × 读者**是否匹配？（如管理层 + 全球 + 标准深度是否可交付）
- **竞品分层**是否与调研目的对齐？
- 「不做/降级」结论是否在用户可接受范围内？

### C.3 结构化采集（AskQuestion，带推荐）

与 [SKILL.md Step 0](../SKILL.md) 表格字段一致：

| 字段 | 选项示例 |
|------|----------|
| 调研目的 | 立项评估 / 技术选型 / 竞品对标 / 融资材料 |
| 深度 | 快速扫描（1–2 天）/ 标准调研 / 深度拆解 |
| 范围 | 国内 / 全球 / 指定区域 |
| 读者 | 管理层 / 产品 / 研发 / 投资人 |
| 硬件扩展包 | 启用 / 不启用 |
| 必证项 | 无 / 拆机验证 / 认证查询 / 供应商询价（可多选） |
| 分析师立场 | **必填，无默认组织**。选项：第一方（自定义身份，如「某司技术规划师」）/ 中立第三方 |
| 我方主体 | 第一方模式下由用户确认；skill 不预设组织或型号 |

竞品分层默认值（可让用户修正）：

- **T0**：直接对标且份额或技术领先
- **T1**：同价位替代
- **T2**：参考观察

## D. Step 0 四段流程

| 子步 | 动作 | 产出 |
|------|------|------|
| **0a 语境扫描** | 读 `$PROJECTS_ROOT/<project_slug>/research/`、检索公开事实 | `调研意图.md` 草稿（初始输入、已知事实、agent 理解） |
| **0b 澄清/压测** | 按清晰度 full(≤8) 或 lite(1–3)；含假设压测 | 交错更新 `调研意图.md` + `调研基调.md` 草稿 |
| **0c 结构化采集** | `AskQuestion` 收集表格字段 | 更新 `调研基调.md` |
| **0d 定稿闸门** | 展示摘要；用户确认后 `Step 0 状态：已确认` | 勾选 `进度.md` 检查点 |

**跳过 Step 0 问询**：`调研基调.md` 已存在且 `Step 0 状态：已确认` → 直接从 `进度.md` 续跑。

## E. Step 1 轻量 grill（≤3 轮）

**触发**：模板生成后、进入 Step 2 前。

**不做**：重复 Step 0 已确认的字段（目的、深度、读者等）。

**典型问法**（一次一题，结构化题带推荐）：

1. **裁剪方案**：给出 2–3 种模板维度方案（如全 13 节 / 砍掉售后与专利 / 假设驱动只保留 §1–§6+§12–§13），**推荐其一**并说明与调研目的、读者的匹配理由。
2. **MECE 挑战**：「§X 与 §Y 是否重叠？是否合并或删一节？」
3. **扩展包确认**（若 0 阶段未完全定）：「硬件扩展包已启用/未启用，模板是否按此定稿？」

确认后更新 `调研模板.md`，勾选 `Step 1 模板确认`。

---

## F. Step 2 轻量 grill（≤3 轮）

**触发**：竞品列表生成后、进入 Step 3 前。

**典型问法**：

1. **T0 覆盖**：「T0 缺 [竞品 X]，是否上调为 T0？」或「[Y] 标为 T0 的依据是？是否应降为 T1？」
2. **分层合理性**：「[Z] 在 T2 但与你方移动形态高度相关，是否上调？」
3. **范围边界**：「间接竞品是否过多？是否砍掉 [列表] 以匹配深度？」

确认后更新 `竞品列表.md`，勾选 `Step 2 竞品列表确认`。

---

## G. 续跑与重做

### 续跑（Step 0 未完成）

- 存在 `调研意图.md` + `调研基调.md`，且 `Step 0 状态：待确认`
- 读 `调研意图.md` 定位**最后未决分支**，从下一题续问
- **不重头** grill，除非用户明确要求

### 续跑（Step 0 已完成）

- `Step 0 状态：已确认` → 跳过 Step 0 问询，从 `进度.md` 当前步骤继续

### 重做 Step 0

- 用户说「重做 Step 0」→ 重新生成 `调研意图.md` + `调研基调.md`
- 旧文件可覆盖；若保留历史，agent 须在 `调研意图.md` 注明「重做于 YYYY-MM-DD」

### 旧项目兼容

- 仅有 `调研基调.md`、无 `调研意图.md` 且 **已确认** → **不强制补写**
- 重做 Step 0 时 **新生成** `调研意图.md`

---

## H. 产出自检（Step 0d 定稿前）

agent 快速检查 `调研基调.md`：

1. `调研议题` 是否一句可复述？
2. `核心决策问题` 是否 3–5 条？
3. 基本参数表是否齐全？**`分析师立场` 是否已由用户填写**（不得留空或代填组织名）？
4. 若立场非「中立第三方」，`我方主体` 是否已确认？
5. 竞品分层是否有依据（可仍为「待 Step 2 细化」）？
6. `Step 0 状态` 是否为 `待确认`（闸门确认后改为 `已确认`）？

`调研意图.md` 无固定章节要求；简流程至少记录：输入清晰度判断、扫描摘要、已问已答摘要。

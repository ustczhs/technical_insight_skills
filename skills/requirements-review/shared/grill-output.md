# Grill 输出格式（选择题）

面向用户的每一道决策题，**默认用选择题**呈现；禁止只丢开放题让用户从零填写。

## 硬格式

```
### 〈题目标题〉

简要依据（Corpus / Web / 上下文，可 1–3 行）

**请选择（单选）（回复选项字母即可；选最后一项时请写上你的内容）：**

A. 〈选项〉
B. 〈选项〉
C. 〈选项〉          ← 可选，2–4 个实质选项为宜
D. 其他（请补充）
```

### 规则

1. **实质选项 2–4 个**（不含自定义项）；过碎则合并，过粗则拆到下一题。
2. **必须标出推荐项**：在推荐选项后加 `（推荐）`，并与硬规则「每个决策必须带推荐答案」一致；推荐项通常放 **A**，除非另有理由。
3. **最后一项固定为自定义入口**，文案：`其他（请补充）`。不要省略。
4. **一次一题**；禁止一批多题。
5. 用户只回 `A` / `同意推荐` / 粘贴推荐项原文 → 视为选中推荐项。
6. 用户回最后一项字母但未写内容 → **追问一句**补全，勿擅自发明。
7. Yes/No 类（如 Ready？）也做成选择题，例如：`A. Ready（推荐）` / `B. 暂不 Ready` / `C. 其他（请补充）`。
8. Do / Defer / Don't **单独成题**时，三项各占一选项，另加最后一项「其他（请补充）」。

## 反例

- 只写「请确认：同意 / 或改写」而无选项列表  
- 自定义项不在最后、或夹在中间  
- 无推荐标记，让用户裸选  
- 选项超过 5 个实质项（应拆题或合并）

## 示例（Corpus Relation）

```
### Corpus Relation

相对已确认 Corpus，本需求更像在既有「回充 + 主机埋点」上补增量。

**请选择（单选）（回复选项字母即可；选最后一项时请写上你的内容）：**

A. Extends（推荐）— 延伸已有能力，有可辨增量
B. Already-covered — 现有埋点已够，需先解消重复
C. New — Corpus 中无对应能力/陈述
D. 其他（请补充）（含 Conflicts / Unknown 及理由）
```
